# Regression Testing

## What is Regression Testing?

Regression Testing is performed after software changes to ensure that existing functionality continues to work correctly and that no new defects have been introduced.

Its purpose is to verify that fixing one issue has not unintentionally affected other parts of the application.

---

## Why is Regression Testing Important?

- Detects side effects caused by code changes.
- Protects existing functionality.
- Maintains software quality.
- Prevents old features from breaking after updates.

---

## When is Regression Testing Performed?

- After bug fixes.
- After adding new features.
- After software updates.
- Before major releases.

---

## Characteristics

- Broad testing.
- Covers multiple areas of the application.
- Can be time-consuming.
- May be automated in large projects.

---

## Example

Bug Fixed:

Restart Race Timer.

Regression Testing may include:

- Launch game.
- Login.
- Main menu.
- Controller input.
- Car selection.
- Track selection.
- Settings.
- Save progress.
- Race completion.
- Exit game.

The goal is to verify that the fix has not affected unrelated functionality.

---

## Regression Testing vs Sanity Testing

Sanity Testing

- Focuses only on the fixed functionality.
- Narrow scope.
- Quick verification.

Regression Testing

- Covers the entire application or major areas.
- Broad scope.
- Ensures no existing features are broken.

---

## Interview Tip

Remember this sentence:

Regression Testing answers:

"Did fixing one issue accidentally break something else?"

---

## Key Takeaways

- Performed after software changes.
- Protects existing functionality.
- Broader than Sanity Testing.
- Helps maintain software stability.
